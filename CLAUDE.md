# AI Time Manager — Claude Code Rules

## a) Фундаментальный контекст

**Стек:**
- React 18 + Vite 5, исходники на чистом JavaScript/JSX (`.jsx`, `.js`) — **TypeScript в проекте не используется**.
- Tailwind CSS 3 (`tailwind.config.js`, `postcss.config.js`) — стилизация только через utility-классы, кастомный CSS в `src/index.css` минимален.
- Zustand — состояние приложения (`src/store/useAppStore.js`).
- react-i18next / i18next — локализация, языки: `ru`, `en`, `de` (`src/i18n/`).
- vite-plugin-pwa + workbox — PWA/service worker (`src/sw.js`, `dev-dist/`, `dist/`).
- Backend — serverless-функции Vercel в `api/` (Node, без фреймворка): `ai.js`, `push-check.js`, `push-schedule.js`, `push-subscribe.js`, `people.js`, `tasks.js`, `shopping.js`, `family-events.js`, `ics-feed.js`, `select-person.js`, `verify-pin.js`, общий код в `api/_lib/`.
- Anthropic SDK (`@anthropic-ai/sdk`) — используется только на сервере (`api/ai.js`), ключ `ANTHROPIC_API_KEY` не должен попадать в клиентский код.
- Upstash Redis (`@upstash/redis`) — хранилище напоминаний/подписок для push.
- web-push — доставка push-уведомлений (VAPID-ключи).
- Деплой — Vercel (`.vercel/project.json`), внешний планировщик — GitHub Actions (`.github/workflows/push-check.yml`, `keepalive.yml`), т.к. Vercel Hobby cron ограничен раз в сутки.

**Структура директорий:**
```
src/
  components/        UI-компоненты (включая components/pages)
  lib/                бизнес-логика/хелперы (дата, категории, streak, погода и т.д.)
  services/           обращения к api/*
  store/              zustand-стор
  i18n/               локализация (ru/en/de)
  App.jsx, main.jsx, sw.js
api/                  Vercel serverless-функции + _lib (общая логика, auth)
public/               статика
dist/, dev-dist/      build-выход (сгенерировано, не редактировать руками)
.github/workflows/    push-check.yml (опрос напоминаний), keepalive.yml (анти-idle для cron)
```

**Ключевые команды (из `package.json`):**
- `npm run dev` — dev-сервер Vite.
- `npm run build` — production-сборка.
- `npm run preview` — предпросмотр собранного билда.
- Тестов и линтера в проекте нет (`test`/`lint` скрипты отсутствуют, ESLint/Prettier не настроены) — **не выдумывай `npm run lint` или `npm test`**, они не существуют. Проверка качества — успешный `npm run build` + ручная проверка в браузере для UI-изменений.

## b) Различающие факторы и UI

- Код на чистом JS/JSX. Не вводи TypeScript, `.ts`/`.tsx`-файлы или связанные зависимости без явного запроса и согласования миграции.
- ESLint/Prettier не подключены — ориентируйся на стиль соседних файлов (кавычки, отступы, отсутствие точек с запятой и т.д.), а не на абстрактные "стандартные" правила.
- В `.claude/skills/impeccable` уже установлен и подключён через хуки (`.claude/settings.local.json`) детектор дизайна Impeccable — он автоматически проверяет UI-правки после Edit/Write и на Stop. Уважай его замечания.
- Для новых API-эндпоинтов повторяй существующий паттерн авторизации (`timingSafeStringEqual` в `api/_lib/auth.js`), а не изобретай новый механизм.
- Локализация — новые пользовательские строки добавляй во все три файла `src/i18n/{ru,en,de}.json`, не хардкодь текст в компонентах.

### Дизайн-система (см. [`DESIGN.md`](DESIGN.md) — полная спецификация с токенами)

Проект имеет выработанный тёмный, почти монохромный UI («The Night Console»): near-black навy-канва, один живой акцентный цвет (персонализируется на человека), плоские тональные поверхности вместо теней, тонкие hairline-разделители, системный шрифт. Перед любой новой UI-работой сверяйся с `DESIGN.md` вместо того, чтобы придумывать цвета/радиусы/тени заново.

**Запрещённые антипаттерны («No AI Slop»)** — не использовать без явного запроса пользователя:
- Шрифты по умолчанию (Inter, Arial, любой импортированный веб-шрифт) — проект намеренно использует системный font-stack, ссылки на Google Fonts недопустимы.
- Серые нейтральные заливки (`bg-gray-100`, `bg-gray-800` и т.п.) — в палитре проекта нет true-gray, только navy/indigo тона (`app-bg`/`app-card`/`app-cardMuted`).
- Градиентный текст (`bg-clip-text` + gradient) — не используется нигде в проекте.
- Неоновые/фиолетовые свечения (`shadow-purple-500/50`, glow-эффекты) — единственный акцент — mint/teal, и он используется точечно (одна интерактивная деталь на экран), см. The One Signal Rule в `DESIGN.md`.
- Рамки слева как «акцент карточки» (`border-l-4 border-blue-500`) — паттерн отсутствует в системе, не вводить.
- Одинаковые квадратные отступы без иерархии (везде `p-4`) — в проекте используется плотная, но осознанная шкала (`p-3`/`px-2`/`py-1.5`), см. Layout в `DESIGN.md`.
- Bounce/elastic-анимации (spring-overshoot) — вся моушн-система проекта использует только деселерацию (`ease-out`, `cubic-bezier(0.16,1,0.3,1)`), см. Elevation/Components в `DESIGN.md`.

**Стандарты типографики и цвета:** использовать только токены из `DESIGN.md` (акцент, navy-нейтрали, priority-цвета), выдерживать иерархию текста (`slate-100` → `slate-300` → `slate-500`), всегда добавлять `transition-colors`/`transition-transform` к интерактивным состояниям, а не менять их мгновенно.

**Моушн и анимации:** минималистичные, но не «мёртвые» — состояния меняются (`hover`, `focus`, `active:scale-*`), длительности короткие (0.16–0.28s), кривая — деселерация, без bounce/elastic. Уважай `prefers-reduced-motion` (уже обработан глобально в `src/index.css`).

## c) Защитные меры (Guardrails)

1. **Не менять существующую структуру папок** (`src/components`, `src/services`, `src/store`, `src/lib`, `api/`) без явного согласования с пользователем.
2. **Не рефакторить соседние/несвязанные модули** при выполнении точечной задачи — правь только то, что относится к задаче.
3. **Секреты только в `.env.local`** (уже в `.gitignore`). Никогда не хардкодить ключи (`ANTHROPIC_API_KEY`, `KV_REST_API_TOKEN`, `VAPID_*`, `PUSH_CHECK_SECRET`) в коде или коммитах.
4. **Перед крупными задачами — обязательная фаза планирования** (Plan mode / согласование подхода с пользователем), прежде чем массово менять файлы.
5. **Не трогать `.github/workflows/*.yml` без явного запроса** — `push-check.yml` и `keepalive.yml` управляют критичной для продакшена доставкой push-уведомлений (был инцидент с исчерпанием квоты Upstash 2026-08-19 → 2026-09-01).
6. Не добавлять новые тяжёлые зависимости (UI-библиотеки, state-менеджеры, тестовые фреймворки) без согласования — проект сознательно минималистичен (Zustand, без Redux/MobX; без готового UI-кита, без тестового раннера).
7. Перед тем как считать задачу завершённой — прогонять `npm run build` и, для UI-изменений, проверять фичу вручную в браузере (тестов нет, это единственный gate).
