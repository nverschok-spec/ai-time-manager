# Техническое задание: "Персональный ИИ-тайм-менеджер и голосовой ассистент" (PWA MVP, v2)

Ты — Senior Fullstack Architect. Нам нужно с нуля разработать и запустить MVP для PWA-приложения "Персональный ИИ-тайм-менеджер и голосовой ассистент".

## 1. Концепция и главная фича

Умный планер с минимальным трением при вводе данных. Пользователь открывает приложение, нажимает кнопку микрофона или пишет текст (например: "Напомни завтра в 15:00 созвониться с Алексом, и найди мне 45 минут на спорт в четверг"), а ИИ:

1. Парсит намерение пользователя.
2. Анализирует текущее расписание и свободные "окна".
3. Предлагает задачи с приоритетами — пользователь подтверждает или правит перед сохранением в календарь.

**Важное изменение по сравнению с исходной идеей:** ИИ не пишет в календарь напрямую и без подтверждения. Он возвращает предложение (draft), которое отображается в UI как карточка "ИИ предлагает: ...", и пользователь одним тапом принимает, правит время/название или отклоняет. Это критично, потому что распознавание намерений не безошибочно, а необратимая запись в расписание без подтверждения — плохой UX при любой ошибке ИИ.

## 2. Требования MVP (обновлено)

1. **Без регистрации на стороне пользователя.** Задачи и настройки хранятся локально в браузере (localStorage/IndexedDB). Пользователь стартует за 1 клик.
2. **API-ключ никогда не попадает в клиентский код.** Все обращения к LLM идут через тонкий серверный прокси (serverless-функция: Vercel Edge Function / Cloudflare Worker). Фронтенд обращается только к своему `/api/ai-parse` эндпоинту, который уже на сервере хранит ключ в переменных окружения и проксирует запрос к Anthropic/OpenAI. Это меняет "без бэкенда вообще" на "без бэкенда для пользовательских данных, но с минимальным прокси-слоем для API-вызовов" — иначе ключ будет виден любому в devtools за 10 секунд.
3. **Мультиязычность (i18n):** немецкий (DE), русский (RU), английский (EN) — все три языка полноценные с первого этапа, без фолбэков и заглушек (проект ориентирован на использование в Германии, DE не может быть второстепенным). Тексты интерфейса — в JSON-словарях (`de.json`, `ru.json`, `en.json`), заполняются полностью на Этапе 2 вместе с версткой UI, а не добавляются позже.
4. **PWA-поддержка:** манифест + сервис-воркер (`vite-plugin-pwa`), установка на главный экран iOS/Android.
   - **Явное ограничение (не баг, а факт платформы):** на iOS Safari Web Speech API работает нестабильно или недоступен в PWA-режиме (standalone), фоновые push-уведомления недоступны, а `localStorage`/IndexedDB может быть очищен системой при нехватке места. Поэтому:
     - Голосовой ввод — это *enhancement*, а не обязательная зависимость: если `SpeechRecognition` недоступен, UI сразу и без ошибок переключается на текстовое поле.
     - Добавляем ручной "Экспорт / Импорт данных" (JSON-файл) в настройках — простая страховка от потери данных при переустановке / очистке кэша, недорого в реализации, важно для доверия пользователя.
5. **Логика расписания и конфликтов** (была не проработана в исходном ТЗ, добавляем явно):
   - В промпт к LLM передаётся не весь календарь, а релевантное окно (например ±7 дней от текущей даты) в компактном структурированном виде (список занятых слотов, а не сырой текст).
   - LLM возвращает строгий JSON (structured output / tool use) со списком предлагаемых задач: `{title, date, start_time, duration_minutes, priority, confidence}`.
   - Если предложенное время пересекается с существующей задачей, сервис ai.js помечает это как `conflict: true` и подсвечивает в UI — не подставляет время автоматически без подтверждения.
   - Если у задачи низкая уверенность распознавания (`confidence < порог`) — она показывается пользователю как "уточните" вместо автосохранения.

## 3. Технический стек

- **Frontend:** React (Vite) + Tailwind CSS + Lucide Icons.
- **Backend (тонкий слой):** одна serverless-функция (Vercel Edge Function или Cloudflare Worker) — единственная точка, где хранится API-ключ и куда идёт запрос от фронтенда.
- **PWA:** vite-plugin-pwa.
- **State / Storage:** Zustand + localStorage (или IndexedDB, если объём данных вырастет) + JSON export/import.
- **AI Logic:** Anthropic API (Messages API, structured output через tool use) с сервера, не с клиента.
- **Localization:** react-i18next (DE, RU, EN — все три полностью с MVP).
- **Voice-to-Text:** Web Speech API с проверкой доступности и graceful fallback на текстовый ввод (обязательно, не опционально).

```
  ai-parse.js           — serverless-функция: хранит ключ, шлёт запрос в Anthropic API (новое)

/src/i18n
  config.js, de.json, ru.json, en.json

/public
  manifest.json, иконки для PWA
```

## 5. Приватность и данные

Приватность — ключевой принцип архитектуры, а не побочный эффект:

- **Данные не покидают устройство.** Все задачи, заметки и настройки хранятся в `localStorage`/IndexedDB конкретного браузера. У каждого члена семьи — полностью изолированное хранилище на своём устройстве; синхронизации между устройствами нет, потому что нет ни аккаунтов, ни общей базы данных на сервере.
- **Владелец проекта (разработчик) не видит данные пользователей.** Так как нет БД и логина, некуда стекаться чужим задачам — их физически негде посмотреть со стороны.
- **Единственный момент, когда текст временно покидает устройство** — это отправка текста задачи в LLM (через наш прокси) для распознавания намерения. Это не сохраняется в базе — прокси только пересылает запрос/ответ, без записи в лог или файл.
  - На проде это отдельно нужно явно выключить в коде serverless-функции: никакого `console.log` тела запроса и никакого хранения истории обращений.
  - Провайдер LLM (Anthropic) обрабатывает этот текст на своей стороне на момент запроса — это стандартная особенность любого сервиса с внешним ИИ-API, а не утечка, но стоит честно обозначить это в UI/настройках одной строкой ("текст запроса временно отправляется ИИ для анализа") — для прозрачности перед семьёй.
- **Экспорт/импорт данных** (JSON-файл) — единственный способ перенести/сохранить данные, полностью в руках пользователя, без облака.

## 6. Деплой и тестирование в семейном кругу

- **Домен не нужен на старте.** Код — в приватном репозитории на GitHub → импорт проекта в Vercel (бесплатный Hobby-план) → автодеплой при каждом пуше в `main`.
- Vercel даёт бесплатный HTTPS-адрес вида `проект.vercel.app` — этого достаточно для:
  - открытия на телефоне и добавления на главный экран как PWA;
  - работы serverless-прокси для API-ключа (тот же Vercel хостит и функцию, и фронтенд).
- Hobby-план бесплатен для личного/некоммерческого использования и не ограничивает число проектов в аккаунте — можно спокойно завести отдельный проект рядом с уже существующим. Общие лимиты (100GB трафика, 1 млн вызовов функций в месяц и т.д.) для семейного теста избыточны, упереться в них практически невозможно.
- Домен и полноценная регистрация пользователей — опциональны, только если проект выйдет за пределы семейного использования.

## 7. Пошаговый план реализации

- **Этап 1:** Инициализация Vite + React + Tailwind. Настройка PWA (`vite-plugin-pwa`) и `react-i18next`. Настройка serverless-функции-прокси и переменной окружения для API-ключа (даже в виде заглушки на этом этапе).
- **Этап 2:** UI — список задач на день, чекбоксы, круговой прогресс, переключатель языков, карточка подтверждения ИИ-предложений.
- **Этап 3:** `ai.js` — сборка компактного контекста расписания, вызов прокси-эндпоинта, парсинг structured output, разметка конфликтов и низкой уверенности.
- **Этап 4:** Связка UI + ИИ-сервиса + localStorage/IndexedDB, экспорт/импорт данных, сохранение при перезагрузке.

Начни с Этапа 1.
